# ورقة عمل سلامة البيانات — Private Diary

هذه ورقة إدخال أولية لنموذج **Data safety**. على مالك الحساب مراجعة إصدار AAB النهائي وكل مكتبة مضمّنة قبل الإرسال؛ Google تجعل المطوّر مسؤولاً عن دقة الإفصاح [1].

| سؤال في Play Console | الإجابة المقترحة لهذا الإصدار المحلي | سببها |
|---|---|---|
| هل يجمع التطبيق أو يشارك أياً من أنواع بيانات المستخدم المطلوبة؟ | **لا** | لا يوجد حساب أو خادم أو تحليلات أو إعلانات أو مزامنة سحابية. المحتوى يبقى في تخزين التطبيق المحلي. |
| هل توجد بيانات تعالج محلياً؟ | نعم، لكن لا تُعد جمعاً أو مشاركة عند بقائها على جهاز المستخدم. | النصوص والصوت والصور والرسومات والإعدادات تعالج فقط لتنفيذ ميزة اختارها المستخدم. |
| هل يوفر التطبيق حذف البيانات؟ | **نعم** | حذف الذكريات فردياً أو استخدام المسح المحلي المؤكد من الإعدادات. |
| هل تُنقل بيانات المستخدم عبر الإنترنت؟ | لا بواسطة التطبيق. | النسخ الاحتياطية يصدّرها المستخدم محلياً ويشاركها بإرادته عبر نظام الجهاز. |
| هل يستخدم التطبيق بيانات بيومترية؟ | لا يجمعها ولا يصل إليها. | نظام التشغيل يتحقق من البصمة أو الوجه عند تفعيل فتح القفل البيومتري. |

## مراجعة إلزامية قبل الضغط على Submit

1. افتح نسخة AAB الإنتاجية التي ستُرفع، وراجع أذوناتها الفعلية ومكتباتها التابعة.
2. تأكد من عدم وجود SDK للإعلانات أو التحليلات أو الأعطال يرسل بيانات إلى طرف ثالث.
3. إذا تغيرت الإجابة إلى «نعم» لأي نوع من البيانات، أكمل نوع البيانات والغرض والمشاركة والتشفير والحذف بدقة قبل الإرسال.
4. أدخل رابط سياسة الخصوصية العام المنشور من `privacy-policy.md`.

حتى التطبيقات التي لا تجمع بيانات مطلوبة ملزمة بإكمال النموذج وتقديم رابط سياسة خصوصية [1].

[1] [Google Play — متطلبات نموذج سلامة البيانات](https://support.google.com/googleplay/android-developer/answer/10787469?hl=en-GB)
